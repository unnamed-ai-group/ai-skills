# Security policy

## Report a concern privately

Do not open a public issue for a vulnerability, leaked credential, private data exposure, or instructions that could cause serious harm.

Contact an organisation owner privately. Until GitHub private vulnerability reporting is configured, email `noah@easysurf.ca` with:

- the affected file or skill;
- what could happen;
- safe steps to reproduce the problem, if available;
- whether any credential or private information was exposed.

Do not include a real password, access token, private transcript, medical record, or confidential client file in the report. Revoke an exposed credential through its provider instead of sending it to us.

## Supported work

This project is experimental. The latest version on `main` is the only version considered for security corrections. Maintainers may remove unsafe content while reviewing a report.

We will acknowledge a report when possible, limit details while the issue is active, and publish a correction note when disclosure is safe.
